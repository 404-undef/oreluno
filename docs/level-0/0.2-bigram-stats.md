# Уровень 0 — этап 0.2: Statistical Bigram Model

## Цель

На этапе 0.2 RustLLM впервые извлекает статистическую информацию из обучающего текста.

После tokenization корпус представлен последовательностью `TokenId`. `BigramStats` считает, какие токены встречаются непосредственно друг после друга, а затем преобразует эти наблюдения в эмпирические вероятности следующего токена.

Это ещё не нейронная сеть и не обучаемая матрица весов. Значения модели напрямую получаются из статистики corpus.

---

## Место в pipeline

```text
text
  ↓
CharTokenizer
  ↓
Vec<TokenId>
  ↓
BigramStats::observe
  ↓
transition counts
  ↓
BigramStats::probabilities
  ↓
distribution
```

Внутренняя последовательность этапа 0.2:

```text
0.2.1 — структура BigramStats
0.2.2 — индексация матрицы и transition counts
0.2.3 — нормализация counts в probabilities
0.2.4 — sampling
0.2.5 — детерминированный PRNG
0.2.6 — generation loop
```

Отдельный `.md` не обязан существовать для каждого микрошагa. Документ выделяется тогда, когда появляется самостоятельный смысловой компонент.

## Основные понятия

### Bigram

Bigram — пара соседних токенов.

Для последовательности:

```text
[A, B, C, D]
```

получаем:

```text
A -> B
B -> C
C -> D
```

Если последовательность содержит `N >= 1` токенов, число соседних переходов равно:

```text
N - 1
```

Примеры:

```text
[]      -> 0 transitions
[A]     -> 0 transitions
[A, B]  -> 1 transition
```

### Transition count

Обозначим:

```text
C(i, j)
```

как число наблюдений перехода:

```text
i -> j
```

Counts отвечают на вопрос:

> Сколько раз этот переход встретился в corpus?

## Математика

### Размер матрицы

Для vocabulary размера:

```text
V
```

существует `V` возможных текущих токенов и `V` возможных следующих токенов.

Поэтому число потенциальных переходов:

```text
V × V
```

Логически `BigramStats` хранит матрицу:

```text
                    next token
                 0     1     2
               ┌────────────────
current  0     │  0     3     1
 token   1     │  2     0     4
         2     │  1     5     0
```

Ячейка `(i, j)` содержит:

```text
C(i, j)
```

### Row-major layout

Матрица физически хранится в одном `Vec<u64>` строка за строкой.

Матрица:

```text
0 1
1 1
```

в памяти:

```text
[0, 1, 1, 1]
```

Плоский индекс вычисляется:

```text
index = row * V + column
```

Для bigram:

```text
index = current * vocab_size + next
```

### Условная вероятность

После накопления counts вычисляется вероятность следующего токена:

```text
P(j | i)
```

Читается:

> вероятность токена `j` при условии, что текущий токен — `i`.

Формула:

```text
P(j | i) = C(i, j) / sum_k C(i, k)
```

Числитель — count конкретного перехода.

Знаменатель — сумма всех переходов, исходящих из `i`.

## Пример `abba`

Tokenizer назначил:

```text
a -> TokenId(0)
b -> TokenId(1)
```

Текст:

```text
"abba"
```

После encoding:

```text
[0, 1, 1, 0]
```

Bigram-переходы:

```text
0 -> 1
1 -> 1
1 -> 0
```

Начальная матрица:

```text
      next
       a  b
     ┌──────
a    │ 0  0
b    │ 0  0
```

После `observe()`:

```text
      next
       a  b
     ┌──────
a    │ 0  1
b    │ 1  1
```

Row-major:

```text
[0, 1, 1, 1]
```

Counts:

```text
C(a, a) = 0
C(a, b) = 1
C(b, a) = 1
C(b, b) = 1
```

Probabilities:

```text
P(a | a) = 0.0
P(b | a) = 1.0

P(a | b) = 0.5
P(b | b) = 0.5
```

## Контракт

### `BigramStats::new`

Создаёт пустую матрицу переходов для vocabulary размера `V`.

```text
V == 0
  -> EmptyVocabulary

V > 0
  -> создать V * V нулевых counters
```

Размер проверяется через `checked_mul`.

### `validate_token`

Проверяет, что `TokenId` принадлежит vocabulary, и возвращает его индекс как `usize`.

```text
TokenId
  ↓
usize conversion
  ↓
index < vocab_size
  ↓
validated usize
```

### `index(current, next)`

Преобразует два токена в row-major индекс:

```text
(current, next)
  ↓
validate_token(current)
validate_token(next)
  ↓
current * V + next
```

### `count(current, next)`

Возвращает число наблюдений перехода:

```text
C(current, next)
```

### `observe(tokens)`

Обрабатывает соседние токены через:

```rust
tokens.windows(2)
```

Для каждого окна:

1. получает `current`;
2. получает `next`;
3. вычисляет matrix index;
4. увеличивает соответствующий count через `checked_add(1)`.

`observe()` имеет накопительную семантику:

```text
observe(A)
observe(B)
```

добавляет статистику обоих входов.

Пустой slice и slice из одного токена допустимы и не создают переходов.

### `probabilities(current)`

Возвращает:

```text
Vec<f64>
```

длины:

```text
vocab_size
```

Каждый элемент представляет эмпирическую вероятность соответствующего следующего токена.

---

## Нормализация

Пусть counts строки:

```text
[3, 1, 0]
```

Сумма:

```text
3 + 1 + 0 = 4
```

После нормализации:

```text
[0.75, 0.25, 0.0]
```

Инвариант:

```text
sum(probabilities) ≈ 1.0
```

Используется `≈`, потому что `f64` хранит многие дробные числа приближённо.

---

## Нет исходящих переходов

Если строка counts:

```text
[0, 0, 0]
```

то сумма равна:

```text
0
```

и выражение:

```text
0 / 0
```

не определяет корректное распределение.

Поэтому возвращается:

```text
BigramStatsError::NoOutgoingTransitions(token)
```

На этом этапе smoothing не применяется.

## Реализация

`BigramStats` хранит:

```rust
pub struct BigramStats {
    counts: Vec<u64>,
    vocab_size: usize,
}
```

`Vec<u64>` выбран как компактное row-major представление матрицы.

Используются checked operations:

```text
checked_mul
checked_add
```

чтобы ошибки арифметики возвращались через `Result`, а не превращались в panic или неконтролируемое переполнение.

---

## Ошибки

### `EmptyVocabulary`

Vocabulary размера `0` не имеет допустимых переходов.

### `MatrixSizeOverflow`

Размер:

```text
V * V
```

не помещается в `usize`.

### `TokenIndexToUsizeOverflow`

Значение `TokenId` невозможно представить как `usize` на текущей платформе.

### `TokenOutOfVocabulary`

`TokenId` существует как числовое значение, но его индекс не принадлежит vocabulary текущего `BigramStats`.

### `MatrixIndexOverflow`

Вычисление row-major индекса не помещается в `usize`.

При корректно созданной матрице и валидных токенах эта ошибка служит дополнительной защитой инвариантов.

### `CountOverflow`

Счётчик конкретного перехода:

```text
current -> next
```

достиг `u64::MAX` и не может быть увеличен.

### `OutgoingCountOverflow`

Суммарное число наблюдений всех переходов:

```text
current -> *
```

не помещается в `u64`.

Эта ошибка относится к сумме строки матрицы, а не к одной ячейке.

### `NoOutgoingTransitions`

Для текущего токена нет ни одного наблюдённого следующего токена, поэтому эмпирическое распределение построить невозможно.

---

## Инварианты

После успешного `new(V)`:

```text
counts.len() == V * V
```

Все counts неотрицательны благодаря типу `u64`.

Для каждого валидного токена:

```text
token.index() < V
```

После наблюдения последовательности из `N >= 1` токенов на изначально пустой статистике:

```text
sum(counts) == N - 1
```

если обработка завершилась без ошибки.

Для успешного результата `probabilities()`:

```text
probabilities.len() == V
```

Для каждого `p`:

```text
0.0 <= p <= 1.0
```

И:

```text
sum(probabilities) ≈ 1.0
```

## Тесты

Статистическая часть этапа 0.2 должна проверять:

- создание нулевой матрицы;
- отказ от пустого vocabulary;
- row-major layout;
- невалидный `current`;
- невалидный `next`;
- корректный подсчёт bigram;
- накопление counts несколькими `observe()`;
- пустой slice;
- один токен;
- out-of-vocabulary token;
- overflow отдельного count;
- нормализацию probabilities;
- сумму probabilities около `1.0`;
- невалидный токен для probabilities;
- отсутствие исходящих переходов.


## Bigram как языковая модель

Bigram оценивает:

```text
P(next_token | current_token)
```

То есть использует ровно один предыдущий токен.

Это простейшая Markov-модель первого порядка:

```text
следующее состояние зависит только от текущего состояния
```

Более длинный контекст модель не учитывает.

---

## Связь с будущим Transformer

Bigram:

```text
P(next | current)
```

Transformer:

```text
P(next | previous context)
```

Способ получения распределения будет существенно сложнее, но конечная задача останется родственной:

> оценить вероятности возможных следующих токенов.

Позже появятся:

- trainable weights;
- logits;
- softmax;
- loss;
- gradients;
- embeddings;
- attention.

---

## Что намеренно не входит в статистическую часть этапа

Пока не реализуются:

- trainable weights;
- logits;
- softmax;
- cross-entropy;
- gradients;
- optimizer;
- smoothing;
- temperature;
- top-k;
- top-p.

---

## Что важно понять

После статистической части 0.2 нужно понимать:

- что такое bigram;
- разницу между sequence length `N` и vocabulary size `V`;
- почему таблица переходов имеет размер `V × V`;
- row-major layout;
- как `N` токенов дают `N - 1` переходов;
- как counts накапливаются;
- что означает `P(j | i)`;
- как counts превращаются в probabilities;
- почему сумма probabilities приблизительно равна `1.0`.
