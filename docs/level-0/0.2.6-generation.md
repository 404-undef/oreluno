# Уровень 0 — подэтап 0.2.6: Generation loop

## Цель

Подэтап 0.2.6 объединяет уже готовые части bigram-модели в цикл генерации:

```text
current TokenId
  ↓
BigramStats::probabilities(current)
  ↓
RandomSource::next_f64()
  ↓
sample_index(...)
  ↓
next TokenId
  ↓
next становится новым current
  ↓
повтор
```

До этого каждый компонент работал отдельно. Теперь `BigramModel` связывает статистику
переходов, sampling и внешний источник псевдослучайных значений.

---

## `BigramModel`

Модель хранит обученную статистику переходов:

```rust
pub struct BigramModel {
    stats: BigramStats,
}
```

PRNG намеренно не хранится внутри модели. Вместо конкретного `Rng` методы получают:

```rust
&mut impl RandomSource
```

Поэтому алгоритм генерации не зависит от конкретной реализации генератора
псевдослучайных чисел.

---

## Выбор одного следующего токена

Метод:

```rust
pub fn next_token(
    &self,
    current: TokenId,
    rng: &mut impl RandomSource,
) -> Result<TokenId, BigramModelError>
```

выполняет один шаг модели:

```text
current
  ↓
probabilities(current)
  ↓
random ∈ [0.0, 1.0)
  ↓
sample_index
  ↓
usize
  ↓
TokenId
```

Текущая реализация:

```rust
let index = sample_index(&self.stats.probabilities(current)?, rng.next_f64())?;

TokenId::from_index(index).ok_or(BigramModelError::InvalidTokenIndex(index))
```

### Ошибки и `?`

`BigramModelError` объединяет ошибки нижележащих компонентов:

```text
BigramModelError
├── Stats(BigramStatsError)
├── Sampling(SamplingError)
└── InvalidTokenIndex(usize)
```

Для `BigramStatsError` и `SamplingError` реализован `From`, поэтому оператор `?`
может автоматически преобразовать их в `BigramModelError`.

Это пример композиции ошибок в Rust: верхний уровень не дублирует ошибки
нижних уровней, а оборачивает их.

---

## Цикл генерации

Метод:

```rust
pub fn generate(
    &self,
    current: TokenId,
    count: usize,
    rng: &mut impl RandomSource,
) -> Result<Vec<TokenId>, BigramModelError>
```

генерирует ровно `count` новых токенов.

Начальный `current` используется только как контекст и не входит в возвращаемый
вектор.

Пример:

```text
current = A
count = 3

A -> B -> C -> D

result = [B, C, D]
```

Каждый выбранный токен становится контекстом следующего шага:

```rust
for _ in 0..count {
    current = self.next_token(current, rng)?;
    generated.push(current);
}
```

При:

```text
count = 0
```

цикл не выполняет ни одной итерации и возвращается пустой `Vec<TokenId>`.

---

## Небольшие особенности Rust

### Shadowing параметра

Внутри `generate()` используется:

```rust
let mut current = current;
```

Это shadowing: новая изменяемая локальная переменная получает значение
неизменяемого параметра с тем же именем.

### `Vec::with_capacity(count)`

```rust
let mut generated = Vec::with_capacity(count);
```

Так как итоговое количество токенов заранее известно, память можно зарезервировать
сразу. Длина вектора при этом остаётся `0`; элементы добавляются через `push()`.

### `&mut impl RandomSource`

`&mut` нужен потому, что получение очередного случайного значения меняет внутреннее
состояние PRNG.

`impl RandomSource` означает, что метод принимает любой тип, реализующий
контракт `RandomSource`.

---

## Проверка заменяемого RNG

В unit-тестах используется контролируемый источник:

```rust
struct FixedRandom {
    value: f64,
}
```

Он реализует `RandomSource` и всегда возвращает заранее заданное число.

Это позволяет проверить sampling и generation loop независимо от SplitMix64.

---

## Тесты

Для `BigramModel` проверяется:

- выбор токена из первого интервала вероятности;
- выбор токена из второго интервала;
- проброс `BigramStatsError`;
- проброс `SamplingError`;
- генерация ровно заданного количества токенов;
- `count == 0` возвращает пустую последовательность;
- предыдущий сгенерированный токен действительно используется как следующий контекст.

После завершения подэтапа весь проект проходит 42 unit-теста.

## CLI-интеграция

В CLI добавлен параметр:

```text
--length <usize>
```

Он задаёт количество генерируемых токенов.

Текущее значение по умолчанию:

```text
0
```

Это означает: если `--length` не указан, генерация не выполняется.

Пример:

```text
rustllm --text abba --length 10 --seed 1
```

`--seed` управляет воспроизводимой последовательностью PRNG.

На текущем этапе стартовым контекстом генерации служит первый токен входного
корпуса:

```rust
tokens.first()
```

Это пока политика CLI, а не часть `BigramModel`.

## Что важно понять

После подэтапа 0.2.6 нужно понимать:

- разницу между выбором одного токена и циклом генерации;
- почему новый токен становится контекстом следующего шага;
- почему начальный токен не обязан входить в результат;
- как `RandomSource` отделяет модель от конкретного PRNG;
- как `From` и `?` соединяют ошибки нескольких уровней;
- зачем при известной длине использовать `Vec::with_capacity`;
- почему `count == 0` естественно обрабатывается самим диапазоном `0..count`.
