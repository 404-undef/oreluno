# Уровень 0.2.4 — Sampling из распределения вероятностей

## Цель этапа

На предыдущем этапе `BigramStats` научился превращать статистику переходов в распределение вероятностей.

Например:

```text
[a -> a, a -> b, a -> c]
counts        = [2, 3, 5]
probabilities = [0.2, 0.3, 0.5]
```

Теперь нужно научиться выбирать **один** следующий токен так, чтобы частота его выбора соответствовала заданному распределению.

Это и есть **sampling** (выборка).

---

## 1. Почему нельзя всегда брать максимальную вероятность

Для распределения:

```text
a = 0.2
b = 0.3
c = 0.5
```

можно было бы всегда выбирать `c`, потому что у него максимальная вероятность.

Но тогда результат полностью детерминирован:

```text
c, c, c, c, c, ...
```

Само распределение `[0.2, 0.3, 0.5]` содержит больше информации:

- примерно 20% выборов должны приходиться на `a`;
- примерно 30% — на `b`;
- примерно 50% — на `c`.

Sampling позволяет использовать всё распределение, а не только его максимум.

---

## 2. Случайное число

Для выбора используется число:

```text
random ∈ [0.0, 1.0)
```

Запись `[0.0, 1.0)` означает:

```text
0.0 <= random < 1.0
```

То есть:

- `0.0` допустимо;
- `0.5` допустимо;
- `0.999...` допустимо;
- `1.0` уже недопустимо.

---

## 3. Представление вероятностей как интервалов

Для распределения:

```text
[0.2, 0.3, 0.5]
```

отрезок `[0, 1)` можно разделить:

```text
0.0        0.2              0.5                    1.0
 |----------|----------------|------------------------|
      0              1                   2
```

Получаем интервалы:

```text
index 0: [0.0, 0.2)
index 1: [0.2, 0.5)
index 2: [0.5, 1.0)
```

Поэтому:

```text
random = 0.13 -> index 0
random = 0.37 -> index 1
random = 0.82 -> index 2
```

---

## 4. Накопленная вероятность (CDF)

Чтобы не строить интервалы явно, вероятности последовательно складываются.

Исходное распределение:

```text
[0.2, 0.3, 0.5]
```

Накопленные значения:

```text
0.2
0.2 + 0.3 = 0.5
0.2 + 0.3 + 0.5 = 1.0
```

То есть:

```text
[0.2, 0.5, 1.0]
```

Это связано с **CDF — Cumulative Distribution Function**, функцией накопленного распределения.

На текущем этапе достаточно понимать CDF практически:

> это сумма вероятностей всех вариантов от начала распределения до текущего элемента.

Алгоритм ищет первый индекс, для которого:

```text
random < cumulative
```

Пример для `random = 0.37`:

```text
0.37 < 0.2 -> false
0.37 < 0.5 -> true
```

Выбирается индекс `1`.

---

## 5. Почему используется `<`, а не `<=`

Для:

```text
[0.2, 0.3, 0.5]
```

границы должны принадлежать следующему интервалу:

```text
[0.0, 0.2)
[0.2, 0.5)
[0.5, 1.0)
```

Поэтому:

```text
random = 0.2 -> index 1
random = 0.5 -> index 2
```

Условие:

```rust
if random < cumulative
```

обеспечивает именно такое поведение.

---

## 6. Нулевая вероятность

Распределение:

```text
[0.0, 0.4, 0.6]
```

является корректным.

При:

```text
random = 0.0
```

для первого элемента:

```text
cumulative = 0.0
0.0 < 0.0 -> false
```

После второго:

```text
cumulative = 0.4
0.0 < 0.4 -> true
```

Поэтому выбирается индекс `1`.

Элемент с вероятностью `0.0` никогда не должен быть выбран.

---

## 7. Контракт `sample_index`

```rust
pub fn sample_index(
    probabilities: &[f64],
    random: f64,
) -> Result<usize, SamplingError>
```

Функция принимает:

- нормализованное дискретное распределение вероятностей;
- заранее полученное случайное число `random`.

Она **не генерирует случайное число сама**.

Это специально отделяет два компонента:

```text
RNG
 ↓
random ∈ [0, 1)
 ↓
sample_index(probabilities, random)
 ↓
выбранный index
```

Так sampling можно тестировать независимо от генератора случайных чисел.

---

## 8. Требования к распределению

Корректное распределение должно удовлетворять следующим условиям.

### Распределение не пустое

Некорректно:

```text
[]
```

Потому что выбирать не из чего.

---

### Каждая вероятность находится в диапазоне `[0, 1]`

Корректно:

```text
0.0
0.25
1.0
```

Некорректно:

```text
-0.1
1.2
```

Также вероятность должна быть конечным числом.

Некорректны:

```text
NaN
+infinity
-infinity
```

Для проверки используется:

```rust
value.is_finite()
```

---

### Сумма вероятностей приблизительно равна `1.0`

Математически:

```text
p0 + p1 + ... + pn = 1
```

Но `f64` хранит многие дроби приближённо.

Поэтому вместо строгого:

```rust
sum == 1.0
```

используется допустимая погрешность:

```rust
const EPSILON: f64 = 1e-12;

(sum - 1.0).abs() < EPSILON
```

`EPSILON` здесь означает максимально допустимое отклонение от единицы.

---

## 9. Почему `f64` неточен

Некоторые десятичные дроби не имеют конечного представления в двоичной системе.

Например:

```text
0.1
1 / 3
```

поэтому компьютер хранит ближайшее представимое число.

В результате вычисления могут давать значения вроде:

```text
0.9999999999999999
```

вместо математического:

```text
1.0
```

Это не ошибка алгоритма — это свойство floating-point арифметики.

---

## 10. Ошибки sampling

Текущий контракт предусматривает:

```rust
pub enum SamplingError {
    InvalidProbability {
        index: usize,
        value: f64,
    },
    InvalidRandomValue(f64),
    InvalidProbabilitySum(f64),
    EmptyDistribution,
}
```

### `EmptyDistribution`

Выбирать не из чего.

### `InvalidRandomValue`

`random` не принадлежит `[0.0, 1.0)`.

### `InvalidProbability`

Конкретный элемент распределения:

- отрицателен;
- больше `1.0`;
- `NaN`;
- бесконечен.

Индекс сохраняется в ошибке, чтобы было понятно, какой именно элемент нарушил контракт.

### `InvalidProbabilitySum`

Все отдельные элементы допустимы, но их сумма не образует нормализованное распределение.

Например:

```text
[0.2, 0.3, 0.4] -> 0.9
[0.2, 0.3, 0.6] -> 1.1
```

---

## 11. Порядок валидации

Логически удобно проверять данные в таком порядке:

```text
1. distribution не пустой
2. random принадлежит [0, 1)
3. каждый probability корректен
4. сумма probabilities ≈ 1
5. cumulative sampling
```

Так ошибка остаётся максимально конкретной.

Например:

```text
[0.2, +infinity, 0.8]
```

должна сообщить о недопустимом элементе, а не только о некорректной сумме.

---

## 12. Последний индекс и floating-point погрешность

После успешной проверки суммы теоретически накопленная вероятность заканчивается на `1.0`.

На практике из-за `f64` возможно значение вроде:

```text
0.9999999999999999
```

Поэтому после цикла допустимо вернуть последний индекс как защиту от микроскопической погрешности:

```rust
Ok(probabilities.len() - 1)
```

Это безопасно только после того, как распределение уже прошло проверку нормализации.

Нельзя использовать произвольный fallback вроде:

```rust
Ok(0)
```

потому что он искусственно увеличил бы вероятность первого элемента.

---

## 13. Инварианты `sample_index`

Для успешного вызова:

```text
probabilities.len() > 0

0.0 <= random < 1.0

для каждого p:
    p конечен
    0.0 <= p <= 1.0

sum(probabilities) ≈ 1.0
```

Результат всегда удовлетворяет:

```text
result < probabilities.len()
```

и элемент с нулевой вероятностью не выбирается.

---

## 14. Связь с BigramStats

Полный pipeline теперь выглядит так:

```text
текст
 ↓
CharTokenizer
 ↓
TokenId[]
 ↓
BigramStats::observe()
 ↓
transition counts
 ↓
BigramStats::probabilities(current)
 ↓
Vec<f64>
 ↓
sample_index(probabilities, random)
 ↓
next index
 ↓
TokenId
```

То есть впервые появляется механизм выбора следующего токена на основании статистики корпуса.

---

## 15. Что пока отсутствует

`sample_index()` получает `random` извне:

```rust
sample_index(&probabilities, 0.37)
```

Это удобно для тестов, но ещё не позволяет самостоятельно генерировать последовательность.

Следующий этап:

```text
0.2.5 — детерминированный PRNG
```

добавит генератор псевдослучайных чисел:

```text
seed
 ↓
PRNG
 ↓
random ∈ [0, 1)
 ↓
sample_index()
```

После этого sampling можно будет включить в цикл генерации текста.

---

## 16. Что важно вынести из этапа

После 0.2.4 нужно понимать следующие идеи:

- вероятность задаёт относительную частоту выбора;
- распределение можно представить интервалами на `[0, 1)`;
- cumulative probability — последовательная сумма вероятностей;
- CDF позволяет выбрать индекс по одному случайному числу;
- интервалы являются полуоткрытыми;
- `random` принадлежит `[0, 1)`, а probability — `[0, 1]`;
- floating-point значения сравниваются с допустимой погрешностью там, где нужна нормализация;
- sampling и RNG — разные ответственности и должны оставаться разделёнными.
