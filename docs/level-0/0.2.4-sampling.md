# Уровень 0 — подэтап 0.2.4: Sampling из распределения вероятностей

## Цель

На предыдущем подэтапе `BigramStats` научился строить распределение вероятностей следующего токена.

Подэтап 0.2.4 добавляет механизм выбора **одного** индекса из этого распределения.

Это и есть sampling.

---

## Место в pipeline

```text
BigramStats::probabilities(current)
  ↓
Vec<f64>
  ↓
sample_index(probabilities, random)
  ↓
next index
```

`sample_index()` не генерирует случайное число самостоятельно.

RNG остаётся отдельной ответственностью:

```text
RNG
  ↓
random ∈ [0, 1)
  ↓
sample_index()
```

---

## Основные понятия

Пусть распределение:

```text
a = 0.2
b = 0.3
c = 0.5
```

Если всегда выбирать максимальное значение, результат будет детерминированным:

```text
c, c, c, c, ...
```

Sampling использует всё распределение:

```text
примерно 20% -> a
примерно 30% -> b
примерно 50% -> c
```

### Sampling и argmax

`argmax` выбирает наиболее вероятный вариант:

```text
[0.2, 0.3, 0.5] -> index 2
```

Sampling выбирает вариант случайно, но с учётом его вероятности.

Это разные стратегии.

---

## Математика

### Диапазон случайного числа

Sampling получает:

```text
random ∈ [0.0, 1.0)
```

Запись означает:

```text
0.0 <= random < 1.0
```

`0.0` допустимо.

`1.0` не входит в диапазон.

### Вероятности как интервалы

Для:

```text
[0.2, 0.3, 0.5]
```

отрезок `[0, 1)` делится:

```text
0.0        0.2              0.5                    1.0
 |----------|----------------|------------------------|
      0              1                   2
```

Интервалы:

```text
index 0: [0.0, 0.2)
index 1: [0.2, 0.5)
index 2: [0.5, 1.0)
```

Примеры:

```text
random = 0.13 -> index 0
random = 0.37 -> index 1
random = 0.82 -> index 2
```

---

## CDF и накопленная вероятность

Исходное распределение:

```text
[0.2, 0.3, 0.5]
```

Накопленные значения:

```text
0.2
0.2 + 0.3 = 0.5
0.2 + 0.3 + 0.5 = 1.0
```

Получаем:

```text
[0.2, 0.5, 1.0]
```

Это связано с **CDF — Cumulative Distribution Function**.

Для текущего этапа достаточно практического определения:

> CDF — накопленная сумма вероятностей от начала распределения до текущего элемента.

Sampling ищет первый индекс, для которого:

```text
random < cumulative
```

Для:

```text
random = 0.37
```

получаем:

```text
0.37 < 0.2 -> false
0.37 < 0.5 -> true
```

Результат:

```text
index 1
```

---

## Почему используется `<`, а не `<=`

Интервалы полуоткрытые:

```text
[0.0, 0.2)
[0.2, 0.5)
[0.5, 1.0)
```

Поэтому:

```text
random = 0.2 -> index 1
random = 0.5 -> index 2
```

Условие:

```rust
random < cumulative
```

обеспечивает именно такое поведение.

---

## Нулевая вероятность

Распределение:

```text
[0.0, 0.4, 0.6]
```

является корректным.

При:

```text
random = 0.0
```

первый элемент:

```text
0.0 < 0.0 -> false
```

второй:

```text
0.0 < 0.4 -> true
```

Поэтому выбирается `index 1`.

Элемент с probability `0.0` никогда не должен быть выбран.

---

## Floating-point и `EPSILON`

Вероятности хранятся как `f64`.

Некоторые десятичные дроби нельзя точно представить в двоичной системе.

Поэтому вместо строгого:

```text
sum == 1.0
```

используется:

```text
sum ≈ 1.0
```

Например:

```rust
const EPSILON: f64 = 1e-12;
```

и проверка:

```text
abs(sum - 1.0) < EPSILON
```

`EPSILON` задаёт допустимую численную погрешность.

---

## Контракт

```rust
pub fn sample_index(
    probabilities: &[f64],
    random: f64,
) -> Result<usize, SamplingError>
```

Функция принимает:

1. нормализованное дискретное распределение;
2. заранее полученное случайное значение `random`.

Возвращает индекс выбранного элемента.

---

## Требования к входным данным

### Распределение не пустое

Некорректно:

```text
[]
```

### `random` находится в `[0, 1)`

Корректно:

```text
0.0
0.25
0.999999
```

Некорректно:

```text
-0.1
1.0
1.1
NaN
```

### Каждая probability конечна

Некорректно:

```text
NaN
+infinity
-infinity
```

### Каждая probability находится в `[0, 1]`

Корректно:

```text
0.0
0.25
1.0
```

Некорректно:

```text
-0.1
1.2
```

Обрати внимание на различие:

```text
random      ∈ [0, 1)
probability ∈ [0, 1]
```

### Сумма probabilities приблизительно равна `1`

```text
sum(probabilities) ≈ 1.0
```

---

## Реализация

Логический порядок работы функции:

```text
1. проверить, что distribution не пустой
2. проверить random
3. за один проход:
   - проверить каждую probability
   - вычислить sum
4. проверить sum ≈ 1
5. отдельным проходом выполнить cumulative sampling
```

### Почему два прохода допустимы

Первый проход:

```text
validation + sum
```

имеет сложность:

```text
O(V)
```

Второй:

```text
cumulative sampling
```

тоже:

```text
O(V)
```

Итого:

```text
O(V) + O(V) = O(V)
```

Асимптотическая сложность остаётся линейной.

Объединение всего в один перегруженный цикл возможно, но ухудшает разделение логики и затрудняет проверку полного распределения до возврата результата.

На текущем этапе два последовательных прохода являются разумным балансом между простотой, корректностью и производительностью.

---

## Защитный fallback последнего индекса

После успешной проверки суммы накопленная probability теоретически должна закончиться на `1.0`.

Но из-за floating-point округления возможно:

```text
0.9999999999999999
```

Поэтому после успешной валидации допустим защитный fallback:

```rust
Ok(probabilities.len() - 1)
```

Он компенсирует только микроскопическую численную погрешность.

Нельзя использовать:

```rust
Ok(0)
```

как общий fallback: это искусственно увеличило бы вероятность первого элемента.

---

## Ошибки

### `EmptyDistribution`

Распределение пусто, поэтому выбирать не из чего.

### `InvalidRandomValue(f64)`

`random` не принадлежит:

```text
[0.0, 1.0)
```

### `InvalidProbability { index, value }`

Конкретный элемент распределения недопустим.

Причины:

- значение отрицательно;
- значение больше `1.0`;
- значение равно `NaN`;
- значение бесконечно.

`index` сохраняется для точной диагностики.

### `InvalidProbabilitySum(f64)`

Каждая отдельная probability допустима, но сумма распределения отличается от `1.0` больше разрешённой погрешности.

Например:

```text
[0.2, 0.3, 0.4] -> 0.9
[0.2, 0.3, 0.6] -> 1.1
```

---

## Инварианты

Для успешного вызова:

```text
probabilities.len() > 0
```

```text
0.0 <= random < 1.0
```

Для каждого `p`:

```text
p.is_finite()
```

```text
0.0 <= p <= 1.0
```

Для распределения:

```text
sum(probabilities) ≈ 1.0
```

Для результата:

```text
result < probabilities.len()
```

Элемент с:

```text
p == 0.0
```

не выбирается.

## Тесты

Подэтап 0.2.4 должен проверять:

- выбор ожидаемых интервалов;
- границы интервалов;
- пропуск probability `0.0`;
- пустое распределение;
- `random < 0`;
- `random == 1`;
- `random > 1`;
- отрицательную probability;
- probability больше `1`;
- `NaN`;
- бесконечную probability;
- некорректную сумму.

Эталон:

```text
probabilities = [0.2, 0.3, 0.5]
```

```text
0.13 -> 0
0.37 -> 1
0.82 -> 2
```

Граничные значения:

```text
0.0 -> 0
0.2 -> 1
0.5 -> 2
```

---

## Что намеренно не входит в подэтап

На 0.2.4 не реализуются:

- генерация случайных чисел;
- seed;
- PRNG;
- temperature;
- top-k;
- top-p;
- alias method;
- reusable CDF object;
- binary-search sampling по заранее построенной CDF.

Эти оптимизации и стратегии имеют смысл после понимания базового sampling.

---

## Что важно понять

После подэтапа 0.2.4 нужно понимать:

- чем sampling отличается от `argmax`;
- как probability превращается в интервал;
- что такое cumulative probability;
- практический смысл CDF;
- почему интервалы полуоткрытые;
- почему `random ∈ [0, 1)`;
- почему probability может быть равна `1.0`;
- зачем нужен `EPSILON`;
- почему sampling и RNG разделены;
- почему два линейных прохода по распределению не меняют сложность `O(V)`.

## Следующий шаг

Подэтап 0.2.5 добавляет детерминированный PRNG:

```text
seed
  ↓
PRNG
  ↓
random ∈ [0, 1)
  ↓
sample_index()
```

После этого RustLLM сможет автоматически получать случайные значения для sampling и приблизится к первой генерации текста.
